# Text descriptions and embeddings

Every image has an offline description generated by Janus-Pro-1B and a 2048-dimensional embedding
of that description. Two description sets exist, and the released models use them differently.

## The two description sets

| Set | Directories | Generator prompt | Used for |
|---|---|---|---|
| Unified | `unified_janus_texts/`, `unified_janus_features/` | three labelled one-sentence fields: *Building density*, *Building characteristics*, *Spatial layout* | training the None and Simple baselines (`train.py --unified-prompt`); every transfer and mechanism evaluation in the paper; the norm of the fixed-random control |
| Prompt A | `text_features/` (strings not released) | "How many buildings are visible in the image? What is the shape of the buildings? How are the buildings distributed in the image?", one sentence each | **training the five released CMCE checkpoints** (`ablation_cmce.py` reads this directory); the paper's legacy-directory substitution table |

The two sets are different tensors for the same images (none of the 8,188 WHU feature files is
byte-identical between them).

### Note on the manuscript

The accepted manuscript describes the unified set as the input for source training, validation
and target testing of all models. For the five CMCE checkpoints released here, the source
training input was the Prompt-A feature set: they were trained by `ablation_cmce.py`, which reads
`text_features/`, and evaluated with `unified_janus_features/`. The transfer numbers reported in
the paper are exactly what these checkpoints produce under that evaluation. Evaluating them with
the Prompt-A features instead (training-matched) gives the values in the paper's legacy-directory
table (Inria, source-only threshold: 50.62 ± 2.85). On Massachusetts, which the paper does not
report for this setting, they give 30.49 ± 2.00. On both targets they exceed the visual-only
baseline in every seed. The None and Simple baselines were trained and evaluated with the unified set.

## Generation

- Model: Janus-Pro-1B, bfloat16, CUDA, evaluation mode.
- Processor: `VLChatProcessor.from_pretrained(..., legacy=False)`.
- Decoding: greedy (`do_sample=False`), `max_new_tokens=128`, `skip_special_tokens=True`.
- No dataset-specific prompt tuning, target labels or generator fine-tuning.
- The exact wording of the unified prompt was not preserved; its output schema (the three labelled
  fields above) is visible in every released string. The released strings and tensors are the
  authoritative inputs.

## Embedding operator

A text-only conversation (the description as the user turn, an empty assistant turn, no image) is
passed through Janus-Pro's `prepare_inputs_embeds`, and the returned token sequence is averaged
over the sequence dimension:

    e = mean over tokens of prepare_inputs_embeds(...)   ->   shape [1, 2048], bfloat16

There is no attention-mask weighting and no normalization. `prepare_inputs_embeds` returns the
language model's input-embedding sequence, not a hidden state of a particular transformer layer.

## Files

- `<stem>.pt`: the embedding of one image, a bfloat16 tensor of shape `[1, 2048]`.
- `<stem>.txt` (unified set only): the generated description.
- `batch_features.pt`: a cache of every embedding of the split with metadata (model name, prompt
  type, feature dimension, dtype, ordered filenames). It is not a sample; the fixed-random control
  reads it to compute the mean embedding norm of the WHU training split.
